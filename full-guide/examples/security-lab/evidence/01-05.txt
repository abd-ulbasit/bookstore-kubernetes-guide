# Transcript for 01-core-workloads/05-statefulsets.md, hands-on steps 1 to 7.
# Tier A: a kind cluster named sf-pilot on one Linux lab host, with a
# Kubernetes v1.37.0 node and a kubectl v1.37.2 client. The cluster is shared
# with other workers, so this run used its own namespace, p01-05-bookstore,
# where the chapter prints bookstore. No other namespace was used.
# Recorded by running the chapter's commands in order from full-guide/.
# `ren FILE` is a shell helper, not a command: it runs sed to rename
# `namespace: bookstore` and the Namespace name in FILE, then pipes the result
# to kubectl apply. The repo manifests were not edited by the run. Every other
# `-n bookstore` and `.bookstore.svc` name became `p01-05-bookstore`.
# The one line that printed a local path shows `kubectl` where the helper
# printed its full path. No other line is edited.
# PriorityClass bookstore-data is cluster-scoped and already existed, so the
# run neither applied nor deleted it.
# The first start of postgres on this host took several minutes, mostly in
# fsync. The database appeared after the Pod reported Ready, so step 1 waits
# for a query to succeed. Attempts before the probe changes in
# 20-postgres-statefulset.yaml were restarted by the liveness probe during the
# first start. Those attempts are not in this transcript.
# An earlier attempt that waited for Ready right after deleting the Pod failed
# with NotFound, so step 4 waits for the replacement to be created first.
# The namespace was deleted at the end. Its PersistentVolume stayed Released
# for a short time, then the Delete reclaim policy removed it. The last two
# lines of the cleanup section are a separate check, run after the first one.
# context: kind-sf-pilot
# server: v1.37.0
