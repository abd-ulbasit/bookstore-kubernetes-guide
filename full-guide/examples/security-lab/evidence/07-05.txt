# while the heavy-install lock was free. They install the pinned Argo Rollouts

# Second session, steps 4 to 8. Tier A, the same kind cluster. Helm v3.22.1
# installs the chart named by its digest in a namespace that enforces
# restricted. The shared lab cluster has no namespace called bookstore, and
# nothing here may touch another worker's objects, so the chapter's namespace
# bookstore is p07-finish-rollouts: every manifest below goes through sed, which
# swaps `namespace: bookstore` for `namespace: p07-finish-rollouts` and the host
# suffix `.bookstore.svc` for `.p07-finish-rollouts.svc`. The shipped manifests
# are otherwise unchanged. The stand-in metric (stand-in.yaml) is the manifest
# the chapter prints: a busybox httpd that serves a success rate of 0 and a p95
# of 1000 seconds, which is what the real queries return for a canary that
# served no traffic, and two AnalysisTemplates with the shipped names that read
# it with the web provider. The path of that file is shown as stand-in.yaml. The
# Prometheus gate itself was NOT run here; step 2b of the chapter tests its
# PromQL offline. A first wait for the Rollout to become Healthy timed out
# because catalog's /readyz also needs Redis, which the chapter's prerequisites
# did not apply; step 6b adds it. The first listing in step 7 was taken while
# the canary ReplicaSet was still scaling down, and step 7b repeats it a minute
# later. Argo Rollouts started with two controller replicas, the chart default.
# Everything created here is removed in step 8, the five CRDs included, and the
# heavy-install lock was taken and released around it.
