# Transcript for 04-scheduling/01-scheduler-and-nodes.md, hands-on steps.
# Tier A: a kind cluster on a Linux lab host, with one control plane and two
# workers, Kubernetes v1.37.0 nodes, kubectl v1.37.2. Context kind-sf-sched.
# The cluster is shared with other workers. This run used its own namespace,
# p04-01-bookstore, and the body below shows bookstore, the name the chapter
# prints, after that substitution (the same rule the earlier 04-01 transcript
# used). The lab cluster was created from an earlier copy of the three-node
# config: the same roles and node image, no zone labels, and the cluster name
# sf-sched. The shipped config, cluster-three-node.yaml, adds zone labels; no
# command in this chapter reads them. Node names are the lab's, verbatim:
# sf-sched-control-plane, sf-sched-worker and sf-sched-worker2. The chapter's
# placeholders use the names your cluster gives its nodes.
# Other substitutions: node sched-lab-worker -> sf-sched-worker and
# sched-lab-worker2 -> sf-sched-worker2 in the commands. The NoExecute taint key
# quarantine=true is a lab-only key used in step 4d and removed in the same step.
# The first attempt of this run is not kept: its wait commands ran before the
# Pod existed, and the Events were read before the scheduler wrote them. The
# commands below are the ones that produced the output. One cleanup delete of
# the Deployment timed out on etcd on this busy host, and the namespace delete
# removed the rest. That line is kept below.
