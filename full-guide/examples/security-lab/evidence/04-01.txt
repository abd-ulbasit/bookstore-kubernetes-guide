# Transcript for 04-scheduling/01-scheduler-and-nodes.md, hands-on steps.
# Tier A: kind, a cluster with one control plane and two workers on a Linux
# host the author controls. Node image kindest/node:v1.37.0, pinned by digest
# in examples/security-lab/kind/cluster-multinode.yaml. kubectl v1.37.2.
# Recorded by running the chapter's commands in order, with one exception: the
# step 5 scheduler comparison (selector-demo) ran before the bypass Pod
# (pin-demo). The chapter shows the bypass first. The lab cluster was
# shared with other runs, so the namespace, policy and label names it created
# carry a p04-01- prefix while running. The substitutions below were applied to
# this transcript afterwards, so the chapter's names read as the reader sees
# them. Node names are the lab cluster's and appear verbatim: sf-sched-control-
# plane, sf-sched-worker and sf-sched-worker2. The chapter's own examples use
# sched-lab-*.
# Substitutions:
#   node-restriction.kubernetes.io/p04-01-pool -> node-restriction.kubernetes.io/pool
#   p04-01-bookstore                           -> bookstore
#   p04-01-deny-nodename                       -> deny-nodename-in-sensitive
#   p04-01-dedicated                           -> dedicated
# The step 3 command was recorded against sched-demo-fixed.yaml, a copy of
# sched-demo.yaml with cpu set to 50m; the chapter names the edited file.
# The first run was this run. Its only failures are the denials and refusals
# the steps set out to show. The taint on sf-sched-worker in the step 7 listing
# was set by another run on the shared cluster, not by this one.
