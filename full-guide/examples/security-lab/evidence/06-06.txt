# Transcript for 06-capacity-and-cost.md (06.06), lab steps 1 to 19.
# Tier A: a kind cluster, Kubernetes v1.37.0, kubectl v1.37.2, helm 3.22.1.
# Host: a Linux lab host. Nothing was created on a cloud account.
#
# Substitutions: the chapter's namespace `bookstore` is `p06-06-shop` in every
# command below, the VPA namespace `vpa` is `p06-06-recommender` and the
# OpenCost namespace `opencost` is `p06-06-costs`. The helm binary ran as
# `helm3`. The manifests and values files are the chapter's, copied into a
# scratch directory and never committed. A chapter line that prints a
# substituted namespace is elided with `# ...`.
# The output came from a lab cluster whose node names differ from the chapter's.
#
# Not run here: kube-prometheus-stack, metrics-server and the load Job itself.
# The lab has no metrics API and no Prometheus, and the install lock was held by
# another run, so the load Job, the VPA recommender and OpenCost were checked
# with server-side dry runs and helm template only. Admission is what these runs
# prove; they do not show that the containers start.
#
# Steps 8 and 9 ran before the load-generator ServiceAccount was added to the
# Job; steps 18 and 19 repeat them with it, in a second scratch namespace.
#
# Deliberate failures: step 3 (a LoadBalancer Service over the spend quota),
# step 7 (a Pod asking for 3 CPU, over the LimitRange maximum), step 11 (a
# VerticalPodAutoscaler before its CRD exists) and step 13 (the OpenCost chart
# with its default security context). The API server refuses each one.
#
# What did not work the first time: the first attempts used other scratch
# namespaces, and their dry runs timed out while the cluster's etcd was slow.
# At the last check (step 17) the scratch namespaces were still terminating,
# and their names are not reused. The VPA chart rendered
# helm test hooks, which failed admission until --skip-tests was added. Without
# a CPU limit on the Pod, the LimitRange injected 500m (step 6). The OpenCost
# chart's defaults fail the restricted profile (step 13).
