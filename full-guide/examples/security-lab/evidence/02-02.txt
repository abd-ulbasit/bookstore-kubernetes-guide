# ===== run 2: steps 2 and 3 on the repaired lab =====
# Tier A: kind v0.33.0 cluster, one node on Kubernetes v1.37.0, kubectl v1.37.2,
# kube-proxy in iptables mode. The cluster is shared with other lab workers.
# Namespace substitution: the chapter says bookstore, this run used
# p02-finish-svc. The manifests are a scratch copy of the repository's
# raw-manifests with the namespace renamed in the objects, in the Service DNS
# names (catalog.p02-finish-svc.svc.cluster.local) and in the Namespace object.
# The database user and name keep the name bookstore. client.yaml is the
# chapter's block with the namespace changed. Nothing else differs.
# Setup is step 1 without orders and rabbitmq, which steps 2 and 3 do not use.
# 40-services.yaml still creates their Services, which have no endpoints.
# What it showed on the way: two earlier attempts of this run waited for the
# catalog rollout before creating the Services, and the wait timed out at 300 s
# with 0 of 3 Pods available. Catalog's readiness check opens REDIS_ADDR, which
# is the redis Service name, and 40-services.yaml creates that Service. The Pods
# turned Ready about a minute after the Services existed. This record applies
# the Services first, as the chapter now orders it. In those attempts kubectl
# printed at most three addresses in `-o wide` ("+ 1 more..."), so the chapter
# reads endpoints with a jsonpath that prints each address and its ready flag.
# The endpoint of a Pod being removed stays in the slice, with ready=false,
# until the Pod is gone: the catalog Deployment has a 5 s preStop sleep and a
# 30 s grace period. The record shows both states, then the end state after 35 s.
# The rollout-continuity loop sends 60 requests, one per second, while
# `kubectl rollout restart` replaces every catalog Pod.
# The namespace delete at the end ran while the lab host was loaded: the client
# timed out and printed a watch error, and the API server was unreachable for
# several minutes. The namespace was gone when the API came back.
