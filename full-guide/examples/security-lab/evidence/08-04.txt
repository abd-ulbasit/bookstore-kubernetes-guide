# Transcript for 08-day-2-operations/04-multi-tenancy-and-namespaces.md.
# Tier A: a kind cluster that the lab owns, shared with other lab runs. The
# Kubernetes server is v1.37.0 and kubectl is v1.37.2.
# Recorded on 2026-10-31 by running examples/security-lab/labs/08-04.sh from
# full-guide/. This is the second run: the first had no Section 4, and the
# Bookstore NetworkPolicy file had since gained an egress policy, so the
# listings below differ from that first run.
# The lab used three namespaces: p08-04-bookstore, p08-04-acme and p08-04-probe.
# The chapter prints bookstore, tenant-acme and probe and applies the same
# files. The script changes only the namespace fields of each file (its rename
# step), so object names are the chapter's own. Lines that name the lab
# namespaces are kept as captured. The chapter's output blocks show only lines
# without a namespace name, and the commands in the chapter use the reader's
# names.
# Section 1 applied the Bookstore namespace's guardrail objects (the namespace
# with its Pod Security labels, the quota and limits, the ServiceAccounts and
# RBAC, and the NetworkPolicies). It did not apply the Bookstore workloads, to
# keep the shared cluster small. The default ServiceAccount in the listing is
# the one every namespace gets.
# Section 2 applied second-tenant.yaml with its namespace renamed.
# Section 4 created three Pods from manifests the script writes: acme-hog in
# tenant-acme, which takes the whole memory quota, and probe and peer in a
# plain namespace with no NetworkPolicy. The two refused creates and the
# refused request are deliberate. The probe namespace is labelled restricted
# and its Pods carry the full baseline. The shell variables in the two exec
# commands are shown unexpanded; they held the Pod IPs.
# The cleanup step deleted all three namespaces and the script ended with its
# last line.
