# Transcript for 05-security/03-supply-chain.md, lab steps 0 to 14, as run.
# Tier A: kind with a Kubernetes v1.37.0 node (kubectl v1.37.2) on a Linux
# Docker host: Ubuntu 26.04.1, kernel 7.0.0, Docker 29.8.2. The registry and the
# cluster ran on that host. The scanners and the signer ran from an operator's
# workstation, which reached the registry through an ssh tunnel on port 5001.
# Versions: Trivy 0.76.1, Syft 1.55.0, Grype 0.121.0, cosign 3.1.4, KubeLinter
# 0.8.3, kubesec 2.15.0, Docker buildx 0.38.1 with the BuildKit (v0.33.1) built
# into the Docker daemon, and registry:3 pinned by digest.
# Recorded by running examples/security-lab/labs/05-03.sh from full-guide/
# against the kind cluster sf-pilot. The script exited 0.
# Steps 11 and 12 need the throwaway cluster p05-supply. This run did not create
# it, so the script skipped them. The chapter cites them and labels them not run.
#
# What did not work the first time:
# - The docker-container BuildKit builder could not start on the Docker host:
#   the daemon reported "failed to discover GPU vendor from CDI". The build uses
#   the daemon's built-in BuildKit instead, which records provenance.
# - cosign 3.1.4 refuses --tlog-upload=false with its default signing config.
#   The lab passes a signing config that names no transparency log. Without an
#   empty COSIGN_PASSWORD, cosign waited for a key password on a terminal.
# - Syft and Grype default to the platform of the machine they run on. The image
#   index holds linux/amd64 only, so the lab passes --platform linux/amd64.
# - A server dry-run cannot see a ServiceAccount that exists only in the dry-run,
#   so the first run refused the baseline Pod. The lab now creates the
#   ServiceAccount first, then dry-runs the Pod against it.
