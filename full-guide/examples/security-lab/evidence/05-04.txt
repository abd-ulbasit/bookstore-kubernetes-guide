# Transcript for 05-security/04-secrets-and-cluster-hardening.md (lab 05.04).
# Tier A: kind on a Linux lab host.
# Versions: kind v0.33.0; node image kindest/node:v1.37.0, pinned by digest;
# Kubernetes v1.37.0 nodes; etcd 3.7.0 inside the node; containerd 2.3.4;
# busybox:1.36 by digest. The kubectl on the lab host was v1.35.5, not
# v1.37.0, and kubectl warned about the version skew. Its output is recorded
# as it printed.
# Recorded by running labs/05-04.sh. Three runs, in this order.
#
# Runs 1 and 2 used earlier revisions of the script, with the aesgcm provider
# and a one-step rotation. They are kept as the record of those runs.
#
# Run 1: MODE=all, on a throwaway kind cluster the script created and named
#   p05-enc. Steps 1 to 8 ran there on the earlier revision. Steps 9 and 10 did
#   not finish: the lab host's disk was saturated, so the Pods never became
#   Ready and the apiserver restarted under them. Step 11 could not delete the
#   cluster until the host freed up; the cluster is gone now.
# Run 2: MODE=inuse, on a second kind cluster the lab owns, in a namespace the
#   run created. Steps 9 to 11 ran here on the earlier revision. The namespace
#   was deleted at the end. Run 2 output never names its cluster.
# Run 3: MODE=all, on a throwaway kind cluster named p05-enc, with the committed
#   script. Steps 1 to 11 ran in one cluster and the cluster was deleted at the
#   end. The chapter's output blocks come from this run. Two earlier attempts
#   to start this cluster failed before its node was ready, and are not
#   recorded here.
#
# Name substitution. The chapter prints secrets-lab for the namespace and
# lab-secrets for the cluster. The captured runs used p05-04-secrets for the
# namespace and p05-enc for the cluster, and the node is p05-enc-control-plane.
#
