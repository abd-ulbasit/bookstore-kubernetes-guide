# Transcript for 05-security/04-secrets-and-cluster-hardening.md (lab 05.04).
# Tier A: kind on a Linux lab host.
# Versions: kind v0.33.0; node image kindest/node:v1.37.0, pinned by digest;
# Kubernetes v1.37.0; kubectl v1.37.0, copied from that node image so the
# client matches the server; etcd 3.7.0; containerd 2.3.4; busybox:1.36 by
# digest.
# Recorded by running labs/05-04.sh. Two runs, in this order.
#
# Run 1: MODE=all, on a throwaway kind cluster the script created and named
#   p05-enc. Steps 1 to 8 ran with the commands the chapter shows. Steps 9 and
#   10 did not finish: the lab host's disk was saturated, so the Pods never
#   became Ready and the apiserver restarted under them. Step 11 could not
#   delete the cluster until the host freed up; the cluster is gone now.
#   Run 1 used an earlier revision of the script. Steps 1 to 8 have the same
#   commands in the committed script; only step titles and the grouping of
#   steps 9 to 11 changed.
# Run 2: MODE=inuse, on a second kind cluster the lab owns, in a namespace the
#   run created. Steps 9 to 11 ran here and are the in-use results the chapter
#   shows. The namespace is deleted at the end.
#
# Name substitution. The chapter prints secrets-lab for the namespace and
# lab-secrets for the cluster. The captured runs used p05-04-secrets for the
# namespace and p05-enc for the cluster, and the node is p05-enc-control-plane.
# Run 2 output never names its cluster.
#
