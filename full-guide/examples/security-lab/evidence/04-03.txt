# Tier A: a kind cluster named sf-sched on one Linux lab host. It has one
# control plane and two workers, each a Kubernetes v1.37.0 node, and the client
# is kubectl v1.37.2. The lab node names (sf-sched-*) are kept as captured.
# The chapter's section 3 creates a fresh cluster from
# examples/security-lab/kind/cluster-three-node.yaml. That step was not run
# here: the lab cluster already existed with idle workers, which is the state
# the fresh cluster gives. No Bookstore workload ran during this capture.
# The cluster is shared with other workers, so this run used its own
# namespaces, p04-finish-batch-lab and p04-finish-team-a, where the chapter
# prints batch-lab and team-a. Its three PriorityClasses carry the prefix
# p04-finish-bookstore-, where the chapter prints bookstore-. The manifests are
# the chapter's own blocks, saved to files under the names the chapter gives
# and applied through the sed expression shown in each command. The
# namespace batch-lab is created by the chapter's filler.yaml, so no file
# outside the chapter is used. The dry-run PriorityClass names (system-example,
# too-high, ceiling) are never created, so they carry no prefix.
# The prefix changes the ReplicaSet and Pod hashes below, and nothing else.
# What did not work the first time: an earlier capture ran the filler in a
# namespace made by a lab-only file, so it never met the Bookstore quota and
# LimitRange that a reader on the ch.02 cluster would meet. The chapter now
# gives the filler a namespace of its own, and this capture uses it. The
# earlier capture also put only the two Bookstore classes in the quota; a
# probe then showed the system class accepted in the tenant namespace, so the
# quota lists the two system classes too. The transcript below is the run on
# the chapter as it now reads, with nothing else running on the workers. It
# completed on the first attempt.
