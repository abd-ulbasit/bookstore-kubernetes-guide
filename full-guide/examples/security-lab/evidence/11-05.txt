# External Secrets Operator chart 2.12.0 (app v2.12.0). Run on 2026-10-31 against
# the lab kind cluster sf-pilot. Every name the chapter prints as `bookstore`,
# `vault` or `external-secrets` is `p11-05-bookstore`, `p11-05-vault` or
# `p11-05-eso` in the commands and output below. The Vault paths
# (secret/data/bookstore/db and database/creds/bookstore-app) keep the chapter's
# names. The Vault role binds the lab namespace p11-05-bookstore.
# Lab copies of the bookstore manifests: the repo file with the namespace
# renamed (a perl one-liner, which leaves image names alone), and each
# priorityClassName line removed. The lab did not create the PriorityClasses,
# because three bookstore-* PriorityClasses already exist on the shared cluster.
# The lab applied the Postgres, Redis, catalog and migration objects of section 0,
# and no orders, storefront or payments objects.
# Vault dev mode and ESO are small installs (one Vault Pod, three ESO Pods). The
# heavy-install lock was taken for the ESO install and released after it.
# Cleanup at the end removed both Helm releases, the ESO CRDs, the Vault and ESO
# ClusterRoles and bindings, and the three namespaces.
# Attempts, and what did not work the first time (kept in the run below, in order):
#   - The first Vault rollout check used `rollout status`. The chart's StatefulSet
#     uses OnDelete, so the check does not apply. The chapter now waits for the Pod.
#   - The first ESO install ran before the chart repository was added on this
#     Mac, so helm refused it. The repository was added and the install repeated.
#   - The first can-i checks ran before ESO existed and answered no. Only the
#     checks after the install are shown in the chapter.
#   - The first SecretStore used a lab copy whose ServiceAccount name had been
#     renamed too. Vault's role names bookstore-eso, so Vault did not match it, and
#     the SecretStore stayed not Ready. The copies were made again with only the
#     namespace renamed, and the SecretStore became Valid.
#   - The namespace stayed Terminating after the first lab copy was deleted. The
#     ESO ExternalSecret kept its finalizer after the SecretStore it used was gone.
#     Its finalizer was cleared with a merge patch, and then the namespace finished.
#   - The first Bookstore copies also renamed the Postgres user and database, so the
#     catalog pod could not match its database. Two rebuilds failed before the
#     third: the namespace was still Terminating, and then a transform joined two
#     lines of the Namespace copy. The fourth pass built from copies that rename
#     the namespace only.
#   - Deleting the synced Secret alone does not start a new sync. The swap was run
#     again with the ExternalSecret deleted too.
#   - Deleting the namespace also removed the ESO scoped Role and RoleBinding, so
#     ESO could not list ExternalSecrets. The release's own RBAC was applied again
#     from `helm get manifest`, and the scoped checks were repeated.
#   - The db-migrate Job did not complete inside its wait in this run. No step here
#     depends on the migration.
#   - Revoking the lease is queued. The role was gone when the count was read again,
#     about 7 seconds later.
#   - `helm uninstall external-secrets` reported a failure at cleanup. The namespace
#     deletion and the object checks after it found no lab object left.
# The password checks connect to the Pod's own address, not to loopback. The
# loopback rules in this Postgres image use trust, so a loopback login would not
# test the password. The pg_hba listing below shows the rules this login used.
