# Commands run in order from the repository root. Terminal colour codes are
# removed. Output is verbatim, including the failed permission checks of an
# early loop, which used the wrong namespace and is kept as run.
# Lab cluster: one kind cluster, sf-pilot, Kubernetes v1.37.0, single control-plane
# node. The chapter prints the reader's names; this cluster has a different name
# and its node name is printed as the lab printed it.
# Versions: kubectl v1.37.2, Helm v4.1.4, chart opencost/opencost 2.5.33 (OpenCost
# 1.121.3, with the image digests the chart pins).
# Substitutions: every namespace named opencost in the chapter ran as
# p13-10-opencost, and the ServiceAccount is p13-10-opencost:opencost. The lab
# has no kube-prometheus-stack and no Prometheus Operator CRDs, so two stand-ins
# and two overrides were used:
#   - Prometheus: a single prom/prometheus:v3.15.1 server in namespace
#     p13-10-prometheus, with no scrape config. OpenCost stops at start without
#     a Prometheus that answers, so the chart's external URL is set to it with
#     --set. The cost series are therefore empty.
#   - ServiceMonitor: opencost.metrics.serviceMonitor.enabled is set to false with
#     --set, because the CRDs are absent.
#   - The namespace prometheus-system was not created. The NetworkPolicy's allow
#     rule selects it and matches no namespace in this cluster.
#   - Lab-only manifests (the Prometheus stand-in, a copy of the NetworkPolicy and
#     a copy of the ConfigMap with the namespace changed) are not in the repository.
# What did not work the first time: the UI crash-looped, because its entrypoint
# writes under /var/www and the read-only root filesystem refused it, so the
# values file turns the UI off and the release was upgraded. The exporter exited
# at start without a reachable Prometheus, and it warned that /var/configs is
# read only, so that path became an emptyDir. The API server was briefly
# unavailable (connection refused, then etcd timeouts), which restarted the
# exporter three times; its final state is Running and ready.
# The probes in the lab: a pod in p13-10-prometheus asked the OpenCost API. With
# the two policies removed the request returned the answer; with them applied it
# timed out. A deliberate failure, shown as such in the chapter.
# Cleanup: helm uninstall removed the release's ClusterRole and ClusterRoleBinding.
# Both lab namespaces were deleted, and no namespace or cluster-scoped object of
# this run remains. No heavy install ran.
