# Transcript for 05-security/02-pod-security.md, lab steps 1 to 12.
# Tier A: a kind cluster, Kubernetes v1.37.0 node, kubectl v1.37.2.
# Node runtime: containerd v2.3.4, runc 1.4.3, crictl 1.36.0.
# Host: Linux, Ubuntu 26.04, kernel 7.0.0, Docker 29.8.2. Not run on macOS.
# Recorded by running examples/security-lab/labs/05-02.sh from full-guide/.
# The cluster name is shown as `security-lab`.
#
# What did not work the first time: the user-namespace Pod (hostUsers: false,
# step 7) did not start on this host. The kube-apiserver accepted the field and
# the kubelet failed to create the sandbox, with runc refused a sysfs mount. The
# cause was not traced further. 01.01 keeps hostUsers out of the baseline until
# it is verified on kind on both Linux and macOS hosts.
#
# Also: a Pod applied straight after `kubectl create ns` can be refused until
# the controller has created the namespace's default ServiceAccount, so the
# script waits for it.
#
# Step 3 reads ca.key but prints only its first ten bytes, the PEM armour.
