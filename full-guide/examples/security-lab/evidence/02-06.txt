# Transcript for 02-networking/06-network-policies.md, hands-on steps 0 to 6.
# Tier A: a kind v0.33.0 cluster on a lab host, one control-plane node on
# Kubernetes v1.37.0, kindnetd image kindest/kindnetd:v20260820-69b56db7,
# kubectl v1.37.2. The cluster is shared with other lab workers.
# Recorded by a script that issues the chapter's commands in
# order. Every command and manifest uses the namespace p02-06-bookstore in
# place of bookstore. The Bookstore files were copied to a scratch directory
# and rewritten in their namespace only. 60-networkpolicy.yaml is that copy.
# Step 3 applies the redis pair after the file, because the file has no
# catalog-to-redis rule and catalog's readiness check reads Redis.
# Step 1 pins the probe image curlimages/curl by digest; the tag is 8.9.1.
# Step 6 uses the kind network's IPv4 gateway as the stand-in address. The
# lab has no metadata service, so 169.254.169.254 times out with or without
# the rule and proves nothing here.
# An earlier attempt on this cluster stopped at step 1 because the control
# plane's kube-scheduler was crash-looping. That attempt is not part of this
# transcript. The run below began after the scheduler was ready.
# The cleanup at the end deletes the probe. The namespace is removed after.

## step 6: egress to the metadata address, with an except
$ cat > worker-egress.yaml <<'EOF'   # the policy as the chapter gives it
$ kubectl apply -f worker-egress.yaml
networkpolicy.networking.k8s.io/allow-worker-https-except-metadata created
$ kubectl label pod probe -n p02-06-bookstore app=payments-worker --overwrite
pod/probe labeled
$ GW=$(docker network inspect kind -f '{{range .IPAM.Config}}{{println .Gateway}}{{end}}' | grep '\.')
$ echo $GW
172.18.0.1
$ kubectl exec -n p02-06-bookstore probe -- curl -sS --max-time 5 https://$GW:443/
curl: (7) Failed to connect to 172.18.0.1 port 443 after 0 ms: Could not connect to server
command terminated with exit code 7
$ sed "s#169.254.169.254/32#$GW/32#" worker-egress.yaml | kubectl apply -f -
