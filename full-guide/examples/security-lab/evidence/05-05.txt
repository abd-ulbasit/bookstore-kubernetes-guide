# Transcript for 05-security/05-kernel-isolation.md.

# Two recorded runs of labs/05-05.sh, joined into one file at the lines that
# start with "## ====".
#
# Run 1, the later one, is a three-node kind cluster whose nodes run Kubernetes
# v1.37.0 and containerd 2.3.4. It ran with P05_SECCOMP=0 and P05_RUNTIME=1 and
# covers steps 1 and 2, then steps 5 to 7. gVisor release 20261026.0 went onto
# one worker node only, and step 7 took it off again. The namespaces in run 1
# carry the chapter's names, so nothing in it is renamed. The checksum lines
# read as they do on Linux: the client that ran the script had no sha512sum,
# and the script put a one-line stand-in for shasum -a 512 on its PATH. In the
# command lines, $WORKER, $GVISOR_RELEASE, $ARCH and $GVISOR_SHA512 are the
# script's variables. Their values are demo-lab-worker, 20261026.0, x86_64 and
# the digest pinned in the script.
#
# Run 2, the earlier one, is a single-node kind cluster, run with
# P05_RUNTIME=0. It covers steps 3 and 4, and the removal of the seccomp
# profiles it copied into its node. The namespace substitution: run 2 named
# its two namespaces p05-05-attack and p05-05-restricted. They appear below as
# kernel-attack and kernel-restricted, the names the chapter uses. The
# exceptions registry reads Pod Security labels from transcripts, and it
# registers the chapter's namespace, not a lab name. That rename is the only
# edit to the recorded lines.
#
# The lab's kind config names its cluster security-lab-kernel, so the node
# names below, demo-lab-* in run 1 and sf-pilot-* in run 2, differ from the
# ones the commands would print on that cluster.
