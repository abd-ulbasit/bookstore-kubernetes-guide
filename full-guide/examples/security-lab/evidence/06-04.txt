# Transcript for 06-production-readiness/04-autoscaling.md, hands-on steps 0 to 3.
# Tier A: a kind cluster, Kubernetes v1.37.0 node, kubectl v1.37.2 client.
# Single control-plane node named sf-pilot-control-plane (the lab cluster's name
# is not the chapter's `kind-bookstore`). Shared cluster: other workers' objects
# are present and were not touched.
# Namespace substitution: the chapter's `bookstore` is `p06-04-bookstore` in
# this run, and `keda` is `p06-04-keda`. The manifests were applied from copies
# with only the namespace names changed. A path in a working copy is written as
# its repository path, examples/bookstore/raw-manifests/.
# Recorded by running the commands in order from the repository root. Terminal
# colour codes are removed. A local API tunnel address is written as <port>.
# Nothing else is edited.
#
# What did not work the first time:
# - 12-redis.yaml was missing from the first apply, so catalog's /readyz failed
#   on Redis and its rollout hit the progress deadline. Applying Redis fixed it.
# - The first apply of 19-payments-worker-deploy.yaml and one rollout check
#   lost the API connection (EOF). Both were re-run.
# - The resource metrics API (v1beta1.metrics.k8s.io) was registered to another
#   worker's metrics-server, which had no endpoints. The HPA therefore reported
#   <unknown> for CPU and never scaled (step 2).
# - No install lock could be taken for KEDA (another worker held it), so KEDA
#   was not installed. Step 3 renders the chart and dry-runs it instead.
# - The KEDA test namespace stayed Terminating after its delete, because the
#   stale v1beta1.metrics.k8s.io discovery failure blocks namespace deletion.
#   The namespace was left to finish once the discovery failure clears.
#
# Not run in this transcript: the load tests and the KEDA scale-out and
# scale-to-zero runs, which need a resource metrics API or a running KEDA.
