# Transcript for 06-production-readiness/05-reliability-and-disruptions.md (06.05), lab steps 1 to 5.
# Tier A: a kind cluster of three nodes (one control-plane and two workers),
# Kubernetes v1.37.0 nodes, kubectl v1.37.2, kind v0.33.0. Host: a Linux lab
# host. Nothing was created on a cloud account. Not run on macOS.
#
# Recorded by running examples/security-lab/labs/06-05.sh once, start to end.
# Everything below is that run's output, unedited. The script creates one
# namespace and deletes it at the end. It cordons one worker for the drain, and
# uncordons it in step 4.
#
# Namespace substitution: the chapter's namespace `bookstore` ran as
# p06-finish-pdb in every command. The ServiceAccounts and the budgets are the
# example tree's 05-serviceaccounts-rbac.yaml and 84-pdb.yaml, copied with the
# namespace renamed. The nodes are named sf-sched-control-plane,
# sf-sched-worker and sf-sched-worker2.
#
# Differences from the chapter's cluster:
# - Two workers, not three. The chapter's kind-multinode.yaml has three, and
#   this lab cluster is shared with other runs, so its shape was fixed. Three
#   catalog replicas therefore sat two on one worker and one on the other, and
#   the drain emptied the worker with two.
# - The three front tiers are stand-ins: a busybox sleeper with the chapter's
#   labels, ServiceAccounts and restricted settings, ready 10 seconds after it
#   starts and stopping 5 seconds after SIGTERM. The Bookstore catalog needs its
#   database to report Ready. The stand-ins have no topology spread constraint:
#   the control-plane is tainted, so catalog's DoNotSchedule hostname spread
#   would leave a third replica Pending on two workers.
# - Neither worker was tainted or cordoned when the run started. The script
#   waits for that, so it does not place Pods on a node another run reserved.
#
# What did not work the first time:
# - The first start of the script waited ten minutes and then refused to run,
#   because another run held a NoSchedule taint (dedicated=database) on one
#   worker. Nothing was created.
# - A second start ran while the lab API server was restarting. It printed EOF
#   and a bare Forbidden for the budget apply, and the stand-ins took longer to
#   start than the script's wait, because the host's disk was busy. It was
#   stopped by hand in step 3, and the next start deleted its namespace. The
#   script then gained a retry for those two API errors, a wait for every Pod to
#   be Ready, and waits on the budget's own status in place of fixed sleeps.
# - The third run completed. Its poller printed one job-control line into the
#   transcript, so the script was changed to end the poller quietly and run
#   again. The run below is the fourth and last.
#
# Deliberate failures: the eviction refused with 429 TooManyRequests at
# minAvailable 3 (step 3), the drain's own retries while the budget reads 0
# (step 4), and the two RBAC checks that the catalog ServiceAccount cannot
# change a budget or create an eviction.
#
# Not run here: the audit record of a budget change, which the chapter cites
# upstream, and a drain on three workers.
