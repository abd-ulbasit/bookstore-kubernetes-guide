Lab transcript for 09.01, the end-to-end Bookstore.
Tier: A (kind). Ran on one shared kind cluster (sf-pilot), Kubernetes v1.37.0,
one node. The chapter's output was captured from a lab cluster with a
different name.
Versions: Traefik chart 42.2.0 (Traefik v3.7.16), helm v4.1.4, kubectl with
the cluster's v1.37 server, cosign with jq for the digest check.
Namespace substitution: the chapter's namespaces bookstore, traefik and client
were run as p09-01-bookstore, p09-01-traefik and p09-01-client. The Traefik
watch lists and the NetworkPolicy namespace selector name the lab namespace.
The prod overlay was copied and renamed in the copy. Its images were pointed at
the kind-loaded dev images, the traefik-rewrite component was added, and the
demo Secret 16-db-credentials.yaml was applied, as the chapter said for kind at the time of this run.
Not run in this first recording: kube-prometheus-stack (06.01), Argo CD
(07.04), Argo Rollouts (07.05), KEDA (06.04), Kyverno (05.07), Velero (08.02)
and the node drain (06.05, which needs two workers). The second recording,
below, ran all of these except the drain.
What did not work the first time: (1) the db-migrate Job started before
Postgres was ready and used up its backoffLimit, so it was deleted and the
overlay applied again; (2) the Postgres volume waited several minutes for the
local-path provisioner on the loaded node; (3) the first npblock manifest had a
mangled command, so it was rewritten and applied again.
Shared-object note: the PriorityClasses bookstore-data, bookstore-critical and
bookstore-batch already existed on the lab cluster from another run. Applying
35-priorityclasses.yaml and the overlay in this run updated them, so their
last-applied annotation and labels changed. Their values match the chapter's
file, and this run did not delete them. A sed rename of the PriorityClass names
in the copy did not apply, so the run used the shared names.
The captured Traefik and namespace names are the lab's; the commands in the
chapter print the reader's names.
Review re-checks: after the chapter was corrected, the Secret step in (d.2) was
rewritten to create db-credentials with a generated password. This run applied the
demo file 16-db-credentials.yaml, which holds the same three keys. No captured
output below depends on which Secret was used. The catalog ServiceAccount check,
the cosign checks and the Kyverno chart check were run again for that review. The
scratch namespace p09-01-rbac was created for the ServiceAccount check and deleted
after it.
Second recording, from the line "# Runner recording for" to the end of this
file: the composed stack on a GitHub Actions runner, with the chapter's own
names and a four-node kind cluster built from the config in (a). Its own
header gives the versions. Run URL:
https://github.com/abd-ulbasit/bookstore-kubernetes-guide/actions/runs/41223339026
It installed metrics-server, Traefik, kube-prometheus-stack, Argo CD, Argo
Rollouts, KEDA, Kyverno and the Velero controller, applied the prod overlay
with the prefix strip, and ran the checks in (e) to (h), (j) and (k). It did
not run a Git remote for Argo CD, a canary Rollout, an object store, a
snapshot-capable CSI driver, a backup, a restore or a node drain.
What did not work on the runner before the recording below:
- The CSR loop in metrics-server's setup checked every request, and a new
  cluster still holds the Approved client requests of its nodes. It now
  selects the kubelet-serving signer.
- Argo CD's Redis image comes from ECR Public by default, and the pull was
  refused with "toomanyrequests: Data limit exceeded" on a first run, so the
  chart install timed out. The install now pulls the same tag from Docker Hub.
- A curl Pod could not resolve cluster names (the edge client printed HTTP
  000, the refusal probe "Could not resolve host"). Docker copies the
  runner VM's DNS search domain into the kind nodes, and curl's resolver stops
  on it. The workflow drops that search line from each node before the lab.
- The KEDA ScaledObject was not Ready: the shipped default-deny policy has no
  rule for the KEDA operator. The recording shows the failure and then a
  lab-only rule that clears it.
- Early versions sent traffic before Prometheus had the targets, so the p95
  query had no increase to read, and printed a command that an address check
  read as an email. Both are fixed in the script.
