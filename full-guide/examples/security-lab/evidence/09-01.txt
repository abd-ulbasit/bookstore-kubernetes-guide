Lab transcript for 09.01, the end-to-end Bookstore.
Tier: A (kind). Ran on one shared kind cluster (sf-pilot), Kubernetes v1.37.0,
one node. The chapter's output was captured from a lab cluster with a
different name.
Versions: Traefik chart 42.2.0 (Traefik v3.7.16), helm v4.1.4, kubectl with
the cluster's v1.37 server, cosign with jq for the digest check.
Namespace substitution: the chapter's namespaces bookstore, traefik and client
were run as p09-01-bookstore, p09-01-traefik and p09-01-client. The Traefik
watch lists and the NetworkPolicy namespace selector name the lab namespace.
The prod overlay was copied and renamed in the copy. Its images were pointed at
the kind-loaded dev images, the traefik-rewrite component was added, and the
demo Secret 16-db-credentials.yaml was applied, as the chapter says for kind.
Not run here: kube-prometheus-stack (06.01), Argo CD (07.04), Argo Rollouts
(07.05), KEDA (06.04), Kyverno (05.07), Velero (08.02) and the node drain
(06.05, which needs two workers).
What did not work the first time: (1) the db-migrate Job started before
Postgres was ready and used up its backoffLimit, so it was deleted and the
overlay applied again; (2) the Postgres volume waited several minutes for the
local-path provisioner on the loaded node; (3) the first npblock manifest had a
mangled command, so it was rewritten and applied again.
Shared-object note: the PriorityClasses bookstore-data, bookstore-critical and
bookstore-batch already existed on the lab cluster from another run. Applying
35-priorityclasses.yaml and the overlay in this run updated them, so their
last-applied annotation and labels changed. Their values match the chapter's
file, and this run did not delete them. A sed rename of the PriorityClass names
in the copy did not apply, so the run used the shared names.
The captured Traefik and namespace names are the lab's; the commands in the
chapter print the reader's names.
