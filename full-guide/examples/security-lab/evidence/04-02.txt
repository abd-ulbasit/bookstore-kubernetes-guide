# control plane and two workers. Kubernetes v1.37.0 nodes, kubectl v1.37.2.
# context: kind-sf-sched
# The lab nodes are sf-sched-control-plane, sf-sched-worker and
# sf-sched-worker2. The chapter's reader cluster names its nodes
# bookstore-control-plane, bookstore-worker and bookstore-worker2. Node names
# below are the lab's, verbatim. The pool node in this run is sf-sched-worker.
# The lab cluster was built before the shipped config gained its zone labels,
# so its nodes carry no topology.kubernetes.io/zone label. The ZONE column in
# the first get nodes is therefore empty here, and no chapter output depends
# on a zone.
# The cluster is shared with other workers, so this run used its own
# namespace, p04-fix-02, where the chapter prints bookstore. The three
# PriorityClasses carry the prefix p04-fix-bookstore-, where the chapter
# prints bookstore-. The pool taint key is p04-fix-dedicated, where the
# chapter prints dedicated, because a taint on a shared worker would hold
# back other workers' Pods. The label node-restriction.kubernetes.io/pool
# keeps its chapter name. The unprefixed label dedicated=database appears only
# in a server dry run, which writes nothing. The substitutions are applied to
# the chapter's own files with the sed expression shown in each command. The
# kubectl patch, scale and get commands name the namespace directly.
# The shipped postgres, catalog and storefront files are applied as they stand
# in examples/bookstore/raw-manifests, apart from those substitutions and one
# edit the chapter shows: replicas: 1 becomes replicas: 0 in the postgres file.
# The images bookstore/catalog:dev and bookstore/storefront:dev were already
# on the lab nodes, so the kind create and kind load steps were not run.
# pool-tenant.yaml is the chapter's own manifest block saved to a file.
# What did not work the first time: an earlier version of the shared postgres
# file required the pool label. The runtime gate applies the shared manifests
# to a one-node cluster, where no node carries the label, and postgres stayed
# Pending. The shipped file prefers the pool label again, and the chapter now
# patches the required rule into the running StatefulSet on this three-node
# cluster. The shipped catalog and storefront files ask for a hard spread,
# which this layout cannot meet, so the chapter shows the Pending Pods and
# then patches the spread. This transcript is the run on the chapter as it now
# reads, and it completed on the first attempt. Its last section runs the
# shared files on a one-node cluster and shows both forms of the rule there.
# Commands run from full-guide/. Node identity checks use
# kubectl --as=system:node:<node> with server-side dry runs. They write nothing.
# Order: the NodeRestriction refusal of the pool label runs first, before the
# administrator sets the label, which is the order the chapter gives. A
# refusal after the label is set would not occur, because NodeRestriction
# refuses only a change of value, so the label refusal cannot be repeated
# once the label exists.
