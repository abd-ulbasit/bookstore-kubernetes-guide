# below are the lab's, verbatim. The pool node in this run is sf-sched-worker.
# The lab cluster was built before the shipped config gained its zone labels,
# so its nodes carry no topology.kubernetes.io/zone label. The ZONE column in
# the first get nodes is therefore empty here, and no chapter output depends
# on a zone.
# The cluster is shared with other workers, so this run used its own
# namespace, p04-finish-02, where the chapter prints bookstore. The three
# PriorityClasses carry the prefix p04-finish-bookstore-, where the chapter
# prints bookstore-. The pool taint key is p04-finish-dedicated, where the
# chapter prints dedicated, because a taint on a shared worker would hold
# back other workers' Pods. The label node-restriction.kubernetes.io/pool
# keeps its chapter name. The unprefixed label dedicated=database appears only
# in a server dry run, which writes nothing. The substitutions are applied to
# the chapter's own manifests with the sed expression shown in each command.
# The images bookstore/catalog:dev and bookstore/storefront:dev were already
# on the lab nodes, so the kind create and kind load steps were not run.
# Order: the NodeRestriction refusal of the pool label runs first, before the
# administrator sets the label, which is the order the chapter gives. A
# refusal after the label is set would not occur, because NodeRestriction
# refuses only a change of value, so the label refusal cannot be repeated
# once the label exists.
# What did not work the first time: the first postgres rollout wait timed out.
# The lab host was under heavy load, the postgres startup probe failed twice,
# and the lab API server restarted once, so kubectl briefly answered Forbidden
# to kubernetes-admin. The wait was repeated and succeeded. Everything after it
# worked on the first attempt. The failed wait is kept below.
