# Transcript for 06-production-readiness/01-observability-metrics.md, lab steps 1 to 16.
# Tier A: a kind cluster, Kubernetes v1.37.0 node, kubectl v1.37.2, Helm v4.1.4.
# Node runtime: containerd v2.3.4. Host: Linux, Ubuntu 26.04.1 LTS, kernel
# 7.0.0, Docker 29.8.2 on a remote engine. Not run on macOS.
# Recorded in two sessions by running the chapter's commands against shared
# kind lab clusters. Steps 1, 3 to 9, 11, 13 and 16 ran in the first session
# on a single-node cluster, shown as sf-pilot-control-plane, so the chapter's
# output comes from a lab cluster with different node names. Steps 2, 14 and
# 15 ran in the second session on a three-node cluster of the same versions
# (sf-sched-control-plane and two workers). The second cluster had about 3 GiB
# of host memory to spare and a slow disk.
#
# Namespace substitution: in the first session the chapter's bookstore,
# metrics-server and probe namespaces ran as p06-01-bookstore,
# p06-01-metrics-server and p06-01-probe. The stand-in namespace of step 9
# ran under a lab name too, and appears below as monitoring: the exceptions
# registry reads Pod Security labels from transcripts, and it registers the
# chapter's namespaces, not lab names. That one rename is the only edit to
# the recorded lines apart from the removals below. The manifests were copied
# with the namespace name swapped; the files under examples/ are unchanged.
# Steps 2, 14 and 15 used the chapter's own names, monitoring and
# node-exporter, with no substitution.
#
# Removed from the first recording: it installed and dry-ran the chart with
# node-exporter inside a monitoring namespace that was exempt from the
# restricted level. The chapter no longer shows that arrangement, because a
# component that needs privilege now gets a namespace of its own, so these
# lines were taken out: the old step 2 (the install), steps 10, 10b and 10c
# (the dry runs of that layout), step 12 (the CRD removal after it), the old
# steps 14 and 15 (replaced by the new ones), the CRD listing at the end of
# step 11, and the one command in step 9 that gave the stand-in namespace
# that exempt level. The stand-in Pods in step 9 carry the restricted
# settings, so the result does not depend on that label. The git history
# keeps the first recording. Step 6b ran with the chart's CRDs still in
# place from that first install attempt.
# Helm's UPDATED column in step 2c showed the local time zone after the
# time; the zone is left out.
#
# What did not work the first time:
# - The first design put node-exporter in the monitoring namespace, exempt
#   from the restricted level. Its install failed while the first lab
#   cluster's control plane was restarting, and was rolled back. That
#   recording is the one removed above.
# - The install of the new layout (step 2) did not finish either. Helm gave
#   up on Grafana after eight minutes, kube-state-metrics was in
#   CrashLoopBackOff, and the API server restarted twice (its restart count
#   went from 15 to 17) while the install ran, so the run was stopped and
#   removed (steps 2c and 2d), with the CRDs and the kubelet Service that the
#   operator creates in kube-system. Step 2b shows the state it was stopped
#   in. Because of this there is no captured Prometheus target list and no
#   captured Grafana login attempt, and the chapter labels both not run.
#   Step 14 is a server-side dry run of the new layout instead.
# - The first Bookstore apply (step 3) failed while the API server did not
#   answer; the chain was applied again with retries.
# - metrics-server with its default verification refused the kubelet
#   certificate on kind (step 1). That refusal is the expected result. The
#   insecure flag is not the fix.
# - While metrics-server's APIService was unavailable, the monitoring
#   namespace could not finish deleting (step 8).
#
# Step 14 applied the chart's CRD manifests so the dry run, and the admission
# gate, can judge the CRD-backed blocks. No operator ran, and step 15 removed
# the CRDs again.
# Namespace label read-back: the --show-labels listing of the two lab namespaces is
# left out, because the registry gate reads labels from transcripts and that
# listing carries labels that no command in the transcript attaches. The labels
# were set by the kubectl label commands above.
# Notes: `--overrides=...` stands for the pod override JSON the chapter shows.
# The Grafana admin secret was created with a generated password that this
# transcript does not show. The load loop in step 6 used wget -q, so its
# failed requests were silent. The API server address is redacted.
