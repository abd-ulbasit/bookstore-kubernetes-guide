# Transcript for 11-advanced-production-patterns/08-ha-control-plane-and-etcd.md.
# Tier A: a kind cluster with one control-plane node. Kubernetes v1.37.0 node,
# kubectl v1.37.2, kind v0.33.0, etcd 3.7.0 (registry.k8s.io/etcd:3.7.0-0).
# Run on 2026-10-31 against the lab kind cluster sf-pilot.
# Substitution: the chapter prints the reader's names. This run used these
# names for them, in every command below:
#   etcd-probe (namespace, ServiceAccount, Pod) -> p11-08-etcd-probe
#   etcd-canary (Secret)                        -> p11-08-etcd-probe
#   The node name in the chapter's sample output is sf-pilot-control-plane;
#   the lab's node has that name, so the output below keeps it verbatim.
# The probe manifest is the chapter's etcd-probe.yaml with the namespace name
# substituted (sed 's/etcd-probe/p11-08-etcd-probe/g'). Nothing else changed.
# Not run, and why:
#   - The three-control-plane cluster (chapter sections 7 and 8). The heavy
#     install lock was held when this run started (see step 0), so no
#     three-member cluster was created and no quorum or node-loss test ran.
#   - Section 9 (full-cluster restore). It needs a kubeadm node.
#   - Manual compaction. The apiserver compacts every five minutes already.
#   - No cloud resource was created.
# What did not work the first time, and what the transcript keeps:
#   - The first snapshot save timed out in the API server's exec stream
#     ("keepalive ping failed"). The save was repeated through the node's
#     container runtime (step 4b), and that run is the one the chapter shows.
#   - The first defragmentation (step 5) hit etcdctl's default 5 s command
#     timeout while the API server was overloaded. The second attempt (step 5b)
#     found the etcd container restarted, so no defragmentation completed. The
#     chapter shows the command and says the result was not captured.
#   - Several reads failed with "Unable to connect to the server" while the API
#     server was overloaded. They are kept; the reads that succeeded are shown.
# Cleanup: the probe namespace stalled in Terminating on the lab cluster. Its
# leftover ServiceAccounts were deleted and its finalizer was removed through
# the finalize subresource. Those commands are not in this transcript.
# Local paths in command lines and local error messages are replaced with
# $LAB_SCRATCH, $LAB_REPO, and the lab host's ssh alias with lab-host. No cluster
# output was changed.
