# Transcript for 01-core-workloads/04-replicasets-and-deployments.md.
# Tier A: a kind cluster with one node on a lab host, Kubernetes v1.37.0,
# kubectl v1.37.2. The cluster is shared with other lab workers, so every
# namespace here is p01-bookstore, and the commands name it in place of
# bookstore. The manifests were copied with that name substituted; the repo
# files are unchanged.
# 20-postgres-statefulset.yaml is the working-tree copy, with the startup probe
# and the wider liveness window that chapter 01.05 adds. That change was not
# committed when this ran. The cache (12-redis.yaml and its Service) joins the
# chain because catalog's readiness pings it.
# What did not work the first time: without the cache, catalog stayed unready
# and the rollout waited. On the loaded node, postgres restarted under its
# liveness probe during crash recovery until the startup probe was added. Those
# attempts are not in this transcript.
# Steps 0 to 6 are the run. Step 7 reads the refusal events with a reason
# filter. Step 8 repeats step 5 in the order the chapter shows it, and its
# output is the one the chapter quotes.
# No operator or chart was installed, so the heavy-install lock was not taken.
# The namespace is deleted after the run. The bookstore-* PriorityClass objects
# from 35-priorityclasses.yaml are cluster-scoped and stay on the cluster.
